# Enhanced RTMP end-to-end test

Meta POV Bridge supports Enhanced RTMP as a second contribution transport alongside SRT:

```text
DAT compressed HEVC
        ↓
Meta POV Bridge
        ↓ no video re-encode
Enhanced RTMP / hvc1
        ↓
Restreamer
```

## Receiver requirement

The RTMP ingest server must support Enhanced RTMP / HEVC. Classic RTMP implementations limited to H.264/AVC are not sufficient.

The current Restreamer environment uses datarhei-core 16.16.0. Enhanced RTMP support was introduced in datarhei-core 16.14.0, so this server generation is compatible. Runtime interoperability still has to be validated with the actual Restreamer publish URL.

## Android / BlueStacks test

1. Select `VIDEO FILE` in BlueStacks, or `PHONE CAMERA` on a physical Android device.
2. Confirm `DAT: MOCK READY` when using MockDeviceKit.
3. Select `RTMP` in the transport selector.
4. Paste the complete RTMP/RTMPS publish URL generated by Restreamer.
5. Tap `START RTMP`.

Expected state:

```text
DAT    STARTED
VIDEO  STREAMING
RTMP   CONNECTED
Frames increasing
MiB increasing
```

## Implementation

RootEncoder RTMP module 2.8.1 is used only for RTMP connection and Enhanced RTMP/FLV packetization.

The app configures:

- `VideoCodec.H265`
- video-only publishing
- 720×1280 video metadata
- 30 fps metadata
- VPS/SPS/PPS through `setVideoInfo()`
- already encoded DAT HEVC media through `sendVideo()`

The DAT video is not decoded and re-encoded by the app.

## Acceptance

RTMP is considered end-to-end validated only when Restreamer:

1. accepts the publish connection;
2. identifies HEVC with a valid 720×1280 resolution;
3. displays a stable visible picture;
4. receives a continuous stream for at least 15 minutes.

Compilation alone does not qualify the RTMP path as validated.
